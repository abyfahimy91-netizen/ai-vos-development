# پرسش‌نامهٔ K1 — ده گفت‌وگو با تعمیرکار
### نسخه ۰٫۱ · ۱۴۰۵/۰۶/۳۰ · سند توسعه ۲٫۵

> **چرا اول این کار؟** ⭐ سه گپِ بازِ ما (`G-53` ایمنی · `G-01`/`G-27` اضطراری ·
> `DATA-04` «چه چیزی نباید عوض شود») ⭐ **همه از وب به دست نمی‌آیند** و هر سه از
> همین ده گفت‌وگو پر می‌شوند. ⭐ ضمناً این تنها کاری است که **فرضیهٔ درآمد** را هم
> می‌آزماید (`K1`). ⭐ **هیچ کدی لازم نیست.** یک فایل، ده تماس، سی دقیقه.

---

## ۱) قبل از تماس — چه چیزی را نباید بگویید

⛔ **وعده ندهید.** نه مشتری، نه پول، نه رتبه. اگر پرسیدند:
> «ما هنوز شبکه را راه نینداخته‌ایم. داریم سازوکارش را می‌سازیم و می‌خواهیم بدانیم
> چه چیزی واقعاً به دردِ شما می‌خورد. جواب‌هایتان محصول را عوض می‌کند.»

⛔ **اسمِ رقیب را نبرید** و فهرست ندهید. ⛔ **هیچ چیزی را روی ضبط نکنید مگر با رضایت.**

⭐ **و این را بگویید چون صداقت‌تان را ثابت می‌کند:**
> «ما هرچه شما بگویید را عمومی نمی‌کنیم. اگر دوست داشتید اسم تعمیرگاهتان کنار حرف‌هایتان
> بماند، می‌ماند.»

## ۲) متنِ شروع (دقیقاً همین)

> «سلام [اسم]. من [نام] هستم. ما یک سایتِ دانشنامهٔ خودرو می‌سازیم و می‌خواهیم بدانیم
> کاری که شما هر روز می‌کنید را **درست** وارد ابزار کنیم. سه سؤال دارم، شاید پنج دقیقه
> وقت‌تان را بگیرد. اگر وقت ندارید بگویید، هیچ اشکالی ندارد.»

⭐ ⭐ **چرا این‌قدر صریح؟** چون جملهٔ «نمی‌دانیم، داریم می‌پرسیم» ⭐ **پاسخِ صادقانه
می‌گیرید** — و پاسخِ صادقانهٔ تعمیرکار دقیقاً همان چیزی است که می‌خواهیم.

## ۳) چهار سؤالِ اصلی — ⭐ هرکدام یک گپ را می‌بندد

### سؤال ۱ — ⭐ زمان  ⇐ می‌بندد: `DATA-05` و `G-22`
> «یک کارِ معمولی که هر روز می‌کنید — مثلاً تعویض لنت جلو — **از وقتی ماشین را تحویل
> می‌گیرید تا تحویل می‌دهید** چقدر طول می‌کشد؟»
>
> سپس: ⭐ **«چقدر از این زمان، کارِ واقعی است و چقدر منتظرِ قطعه یا مشتری؟»**

| کار | زمانِ کل | زمانِ واقعی | علتِ تأخیر |
|---|---|---|---|
| | | | |

⭐ **علتِ تأخیر مهم‌تر از خودِ زمان است** — ⭐ همان چیزی است که دردِ «منتظر قطعه بمونی» را
قابلِ حل می‌کند.

### سؤال ۲ — ⭐⭐ «چه چیزی را **نباید** عوض کرد»  ⇐ می‌بندد: `DATA-04` ⭐ قابلیتِ شاخص
> «خیلی وقت‌ها مشتری می‌آید و می‌گوید [فلان قطعه] خراب است. **کِی تایید می‌کنید که واقعاً
> خراب است؟** و کِی می‌گویید «نه، این را عوض نکنید، مشکل از جای دیگری است؟»

| چیزی که مشتری فکر می‌کند خراب است | چطور ثابت می‌کنید | ⭐ **چه چیزی نباید بدون تأیید عوض شود** |
|---|---|---|
| | | |

⭐⭐ **این جدول در هیچ‌جای ایران وجود ندارد** ⭐ و مستقیم می‌شود «برگهٔ مراجعه» و
«تأییدِ تعمیرکار».

### سؤال ۳ — ⭐ «چه چیزی را **نباید** رانید»  ⇐ می‌بندد: `DATA-09` و `G-53`
> «مردم گاهی با ماشینی می‌آیند که **اصلاً نباید** با آن رانند. کِی به کسی می‌گویید
> **همین‌جا نگه دارید، با این نباید رانید؟**»

| چیزی که کاربر می‌آورد | ⭐ حکمِ شما | جملهٔ عینِ خودِ شما |
|---|---|---|
| | ⛔ اصلاً نباید رانند | |
| | 🟠 با احتیاط | |
| | 🟢 مشکلی ندارد | |

⭐⭐ **جملهٔ عینِ شما** را بنویسید، ⭐ نه بازنویسیِ ما. ⭐ کاربر با لحنِ یک مکانیکِ واقعی
باور می‌کند، نه با متنِ سایت.

### سؤال ۴ — ⭐⭐ آزمونِ پول: `K1`  ⇐ آیا کلِ مدلِ کاری ما ممکن است؟
> «فرض کنید یک نفر با ماشین خراب می‌آید، ما تشخیصِ اولیه را قبل از آمدنش به شما می‌دهیم و
> شما قبول می‌کنید. **برای هر کاری که انجام می‌دهید، چقدر انتظار دارید بگیرید؟**»

| پاسخ | عدد | شرط‌هایی که خودش اضافه کرد |
|---|---|---|
| حداقل | | |
| معمول | | |
| ایده‌آل | | |

سپس ⭐⭐ **دو سؤالِ حیاتی:**
> **الف)** «برای اینکه قبول کنید، چه چیزی لازم است؟ ⭐ (نقدی؟ تضمینِ پول؟ فاکتور؟ نداشتنِ رقیب؟)»
> **ب)** «اگر بیمارداش روی این پلتفرم بیاید و شما کارِ خوبی بکنید، ⭐ **می‌ترسید مشتری‌های
> فعلی‌تان را از دست بدهید؟**»

⭐⭐ پاسخِ «ب» مهم‌ترین دادهٔ این سشن است: ⭐ **اگر بیشترشان بگویند می‌ترسند، مدلِ
کمیسیون شکسته است** و باید قبل از هر کدی عوض شود.

### سؤال ۵ — تواناییِ منفی  ⇐ `L-25`
> «چه ماشین‌هایی را قبول نمی‌کنید؟ چه کارهایی را انجام نمی‌دهید؟»

| نمی‌پذیرم (خودرو) | نمی‌انجام‌دهم (کار) | ⭐ چرا (اگر گفت) |
|---|---|---|
| | | |

⭐ ⭐ **«چه کاری را نمی‌پذیرید» ارزان‌ترین شواهدِ منفیِ کلِ پروژه است** ⭐ — برای
خرابی‌ها باید صدها نفر بنویسند (`G-30`)، ولی این را ده نفر در دو دقیقه می‌گویند.

### سؤال ۶ — پرسشِ کنجکاو (ولی پرسیده شود)
> «کاربری که کمتر از همه حرف می‌زند ولی بیشترین وقت را می‌گیرد، معمولاً چه کسی است؟»
