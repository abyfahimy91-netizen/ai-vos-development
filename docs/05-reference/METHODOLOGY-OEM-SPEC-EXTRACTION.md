# روش‌شناسی استخراج مشخصات رسمی خودرو
**نسخهٔ ۱.۱ — ابزار نسخهٔ ۳، صحت‌سنجی‌شده · ۱۴۰۵/۰۷/۰۷**

> هدف: تبدیل «یک نفر برود و بخواند» به «یک اسکریپت برود و پر کند».
> این سند از کار دستی روی `saipa-citroen.com` استخراج شده است.

---

## اصل حاکم

> **کارخانه ملاک است، نه سایت‌های مقایسه‌گر.**

شاهد: برای موتور M15 سایپا، سایت‌های مقایسه‌گر عدد ۱۱۳ نیوتن‌متر دادند (یا اصلاً ندادند)،
ولی سایت رسمی **۱۲۸ نیوتن‌متر در ۴۰۰۰ دور** نوشت. ما هم ۱۱۳ را از پیش ثبت کرده بودیم.
⇒ اگر کارخانه نباشد، داده یا ناقص است یا غلط.

## مرحله ۱) پیدا کردن منبع رسمی

| اولویت | منبع | چطور پیدا می‌شود |
|---|---|---|
| ۱ | **سایت نمایندهٔ رسمی در ایران** | نام برند + سایپا / ایران خودرو / بهمن خودرو |
| ۲ | **پرتال مستندات فنی جهانی** | `service.<brand>.com` — دفترچهٔ رسمی و Documentation Technique |
| ۳ | سایت خود کارخانهٔ مادر | برای خودروی مونتاژی |
| ۴ | کاتالوگ PDF رسمی | گاهی فقط PDF دارد |
| ۵ | فقط در نبود بالا | سایت مقایسه‌گر، با `data_quality='market'` | **نمونهٔ واقعی:** `saipa-citroen.com` منبع دست‌اول است چون سیتروئن در ایران مونتاژ می‌شود
و مشخصات **مونتاژ ایران** با مشخصات جهانی فرق دارد.

> ⛔ `saipa.ir` از سرور پاسخ نمی‌دهد (دیتایسنتر خارجی بلاک می‌کند).
> باید از **مرورگر** باز شود و خروجی با فایل به سرور برسد.

## مرحله ۲) استخراج — ترتیب دقیق کار

این ترتیب از ۶ خودروی استخراج‌شده یاد گرفته شده و **ترتیبش مهم است**:

1. **اول تیپ را ببین.** صفحهٔ کارخانه معمولاً جدول «تیپ» دارد (تیبا: معمولی/آپشنال ·
 ساینا: ۴ تیپ · C3 XR: فقط V1). **هر تیپ یک ردیف جداست.**
2. **بعد موتور.** کد موتور، حجم، حداکثر قدرت، حداکثر گشتاور.
 ⚠️ **دور موتور را حتماً بگیر.** `114HP/5500rpm` و `114 اسب` دو دادهٔ متفاوت‌اند.
3. **سپس گیربکس، فرمان، ترمز** — اینها بین تیپ‌ها فرق می‌کنند (ساینا: دستی در برابر CVT).
4. **بعد ابعاد، وزن، صندوق، مصرف، باک.**
5. **در آخر چک‌لیست تجهیزات** — معمولاً یک ستون برای هر تیپ دارد ⇒
 `availability` هر تیپ مشخص می‌شود.
6. **استاندارد آلایندگی** و سایر استانداردها.

---

## مرحله ۳) نگاشت به استاندارد KVS

| آنچه در سایت هست | کد KVS |
|---|---|
| نوع / تیپ | `veh_variant.trim_name_fa` + `model_plate` |
| کد موتور، حجم، توان، گشتاور | `veh_powertrain` + `spec_value` |
| `حداکثر قدرت 114HP/5500rpm` | `engine.power_hp` + `engine.power_rpm` — **هر دو لازم** |
| `حداکثر گشتاور 190NM/1500-3500` | `engine.torque_nm` + `torque_rpm_min/max` — **بازه، نه یک عدد** |
| طول/عرض/ارتفاع/محور/وزن/صندوق | `dim.*` |
| مصرف ترکیبی | `eff.fuel_combined` |
| نوع گیربکس + کد | `gearbox.type` + `gearbox.code` (`EAT6`, `6DCT`) |
| سیستم سوخت رسانی | `engine.fuel_delivery` (`GDI`/انژکتوری/کاربراتور) |
| تعلیق جلو/عقب، ترمز جلو/عقب | `chassis.*` |
| چک‌لیست تجهیزات | `veh_option_catalogue` + `veh_variant_option` |
| استاندارد آلایندگی | `eff.emission_standard` | **واحدهای استاندارد KVS:**
`mm` `kg` `L` `cc` `hp` `kW` `Nm` `rpm` `km/h` `s` `L/100km` `Wh/km` `kWh` `kW` `km` `rial`

## مرحله ۴) قوانین ثبت

1. **`source_id` و `observed_at` اجباری‌اند** — بدون منبع، ردیف ثبت نمی‌شود.
2. **مقدار عددی و متنی جدا** — `spec_value` و `spec_value_text`. ستون اول فقط `numeric` است.
3. **عدد صحیح بدون ممیز** — `1461.0` باید `1461` باشد.
4. **مقدارِ تغییرکرده = رکورد جدید با تاریخ جدید**؛ رکورد قدیمی با `observed_at - 30`
 کهنه می‌شود تا تاریخچه بماند (اصل «هیچ‌چیز حذف نمی‌شود»).
5. **`data_quality`:** کارخانه ⇒ `official` · مقایسه‌گر ⇒ `market` · حدس ⇒ `inferred`
6. **مقدار غیرقابل‌باور ثبت نشود** (دروازهٔ `data_quality.plausible`).

## مرحله ۵) بازبینی

- [ ] تیپ‌ها با ستون «تیپ» صفحهٔ کارخانه تطبیق دارد
- [ ] دور موتور دارد؟ اگر نه، پیگیری شود
- [ ] چک‌لیست تجهیزات به تیپ درست نسبت داده شده؟
- [ ] موتور مشترک بین مدل‌ها فقط **یک‌بار** ثبت شده (M15 بین تیبا/ساینا/کوییک)
- [ ] `/data-gaps/` به‌روز شد
- [ ] تست سایت اجرا شد

| # | دام |
|---|---|
| ۱ | ⛔ **جدول مشخصات در دفترچهٔ راهنما «تصویر» است، نه متن.** ۱۳۸۶ فصل داریم ولی جدول مشخصات نداریم ⇒ PDF + OCR |
| ۲ | ⛔ **موتور مشترک بین چند مدل** — ثبت جداگانه یک عدد را ۳ بار وارد می‌کند و ممکن است ناسازگار شود |

| ۴ | ⛔ **سایت‌های مقایسه‌گر ۲۲٪ اختلاف دارند** (۱۱۴ در برابر ۱۳۶ اسب برای یک خودرو) |

## ابزار

```
/opt/carnameh/extract_oem.py — استخراج‌کنندهٔ نیمه‌خودکار
 ورودی: متن استخراج‌شده از صفحهٔ محصول (کپی از مرورگر)
 خروجی: فایل seed آمادهٔ اجرا برای KVS
 نیاز: اجرا از مرورگر (نه سرور) — سایت‌های ایرانی از سرور بلاک‌اند
```

```bash
python3 extract_oem.py --text specs.txt --brand-code SAIPA-CITROEN \
 --model-code SC-C3XR --model-fa "سیتروئن C3 XR" \
 --variant V1 --source-id SRC-SAIPA-C3XR --out seed.sql
psql -f seed.sql
```

# نتیجهٔ صحت‌سنجی ابزار (نسخهٔ ۳)

دو خودرو — ساینا و سیتروئن C3 XR — با **استخراج دستی** مقایسه شد:

> **۲۵ از ۲۵ مشخصه درست — صد درصد.**

## سه باگی که تست گرفت (و رفع شد)

| باگ | چه می‌ساخت |
|---|---|
| الگوی عددی شامل فاصله | از ستون‌های جدول رد می‌شد ⇒ «۴۲۱۵۴۲۱۵۴۲۱۵۴۲۱۵» به‌جای ۴۲۱۵ |
| کلیدواژهٔ سوخت در کل متن | «فرمان **برقی**» ⇒ خودرو **برقی** تشخیص داده می‌شد |
| «حجم» بدون قید | به «حجم **صندوق**» می‌چسبید ⇒ ۳۷۰ به‌جای ۱۵۰۳ | ## قاعدهٔ طلایی (از همین تست‌ها درآمد)

> **عدد را هیچ‌وقت از متن سراسری نگیر.
> اول سلول جدول را بگیر، بعد عدد را از داخل همان سلول بخوان.**

همین قاعده برای تشخیص پیشرانه هم صدق می‌کند: فقط سلول «نوع گیربکس» و
«نوع سوخت» را نگاه کن، نه کل صفحه.

## اجرا

```bash
python3 /opt/carnameh/extract_oem.py \
 --text specs.txt --brand-code SAIPA-CITROEN --model-code SC-C3XR \
 --model-fa "سیتروئن C3 XR" --variant "V1" --variant-code SC-C3XR-V1 \
 --source-id SRC-SAIPA-C3XR --url "<آدرس صفحه>" \
 --year-from 1404 --year-to 1405 --out seed.sql
```

خروجی همیشه بخش «استخراج‌نشده» را فهرست می‌کند — **آن را نادیده نگیر**،
چون روش‌شناسی می‌گوید اسکریپت حدس نمی‌زند.
