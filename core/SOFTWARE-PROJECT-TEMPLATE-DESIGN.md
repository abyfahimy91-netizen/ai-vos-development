# AI-VOS Software Project Template Design

Version: 0.1

## Purpose

This document defines the standard structure of software projects created and managed by AI-VOS.

The purpose is to ensure that any AI system can understand, analyze, continue and develop a software project using repository information.

---

# Design Principles

AI-VOS software projects must:

- Have clear documentation before development.
- Store important decisions permanently.
- Separate business, product, technical and operational information.
- Support continuation by different AI systems.
- Reduce assumptions and missing context.
- Maintain development history through Git.

---

# Standard Project Layers

Every software project should contain these main layers:

## Project Memory

Purpose:

Store permanent project knowledge.

Contains:

- Project identity.
- Current state.
- Decisions.
- Tasks.
- Roadmap.

---

## Business Layer

Purpose:

Define why the project exists.

Documents:

- Business requirements.
- Business model.
- Target users.
- Market objectives.

---

## Product Layer

Purpose:

Define what should be built.

Documents:

- Product requirements.
- Features.
- User stories.
- Product roadmap.

---

## Design Layer

Purpose:

Define user experience and interface standards.

Documents:

- UX design.
- UI guidelines.
- Design system.

---

## Architecture Layer

Purpose:

Define how the system is built.

Documents:

- Technical architecture.
- Database design.
- Security design.
- API design.
- Technology decisions.

---

## Development Layer

Purpose:

Contain implementation resources.

Contains:

- Source code.
- Tests.
- Configuration.
- Development documentation.

---

## Operations Layer

Purpose:

Manage deployment and maintenance.

Contains:

- Deployment instructions.
- Monitoring.
- Backup procedures.
- Change logs.

---

# AI Project Understanding Process

When AI starts working on a software project, it must understand:

1. Business purpose.
2. User requirements.
3. Product goals.
4. Technical architecture.
5. Current development state.
6. Previous decisions.
7. Next required actions.

---

# Localization Requirements

Software projects must explicitly define localization requirements.

Examples:

- Language.
- Text direction.
- Calendar system.
- Number format.
- Currency.
- Regional requirements.

Example:

Persian projects may require:

- fa-IR language.
- RTL interface.
- Persian calendar.
- Persian numbers.
- Iranian business rules.

---

# Security Requirements

Security must be considered from project beginning.

Projects should define:

- Authentication.
- Authorization.
- Data protection.
- Secure coding practices.
- Logging.
- Backup strategy.

---

# Development Documentation

Every important development decision must be documented.

Examples:

- Why a technology was selected.
- Why an architecture was chosen.
- Why a feature was implemented.

---

# Git Repository Rules

Every project repository should maintain:

- Documentation history.
- Code history.
- Decision history.
- Task history.

Major changes should include:

- Implementation.
- Documentation update.
- Commit message.
